## 摘要
Python入门编程要求学生能够表征问题、开发并测试程序、调试错误，并在新情境中应用计算思想。本文对一套为包含16个实验的Python入门课程开发的集成学习生态系统进行了以制品为中心的设计分析。分析语料包含18件教学制品：课程大纲、平板启发式主页以及实验1–16。我们考察了课程导航、问题表征、支架、独立迁移、应用开发、调试、AI集成与评估。15个支架式实验均包含七个要素：输入—处理—输出（IPO）推理、教师引导编程、独立任务、Google Colab/Gradio扩展、调试支持、任务清单和提交要求。实验16作为基于Pygame的综合标志性作业，脱离了该结构。分析识别出四个相互关联的设计特征：协调多种工具的导航层；两种迁移形式，即从引导性问题到独立问题以及从控制台程序到交互式界面；教师端AI增强沟通与学生端AI辅助的不同角色；以及从重复支架向综合问题解决的转变。该案例还指出了尚未解决的矛盾，涉及工具碎片化、可访问性、界面干扰、学生作者身份以及对AI的过度依赖。由于未考察学生学习结果，我们不对教学有效性作出主张。相反，本文提供了一个透明的设计先例，并指出了未来实证评估的优先事项。演示 - https://xinxingwu-uk.github.io/COS107_Demo/Homepage/index.html 源代码 - https://github.com/xinxingwu-uk/Course_Integrated_Learning_Ecosystem

## Abstract
Introductory programming requires students to represent problems, develop and test programs, debug errors, and apply computational ideas in new contexts. In this paper, we present an artifact-centered design analysis of an integrated learning ecosystem developed for a 16-lab introductory Python course. The analyzed corpus comprises 18 instructional artifacts: the course syllabus, a tablet-inspired homepage, and Labs 1-16. We examined course navigation, problem representation, scaffolding, independent transfer, application development, debugging, AI integration, and assessment. All 15 scaffolded labs shared seven elements: input-processing-output (IPO) reasoning, instructor-guided programming, an independent task, a Google Colab/Gradio extension, debugging support, a task checklist, and submission requirements. Lab 16 departed from this structure as an integrative Pygame-based Hallmark Assignment. The analysis identifies four connected design features: a navigation layer that coordinates multiple tools; two forms of transfer, from guided to independent problems and from console programs to interactive interfaces; distinct roles for instructor-side AI-enhanced communication and student-side AI assistance; and a transition from repeated scaffolds to integrative problem solving. The case also identifies unresolved tensions involving tool fragmentation, accessibility, interface distraction, student authorship, and overreliance on AI. Because student learning outcomes were not examined, we make no claims about instructional effectiveness. Instead, the paper offers a transparent design precedent and identifies priorities for future empirical evaluation.
