## 摘要
高等教育中的评估规模化面临两个相互交织的瓶颈：编写评估内容带来的认知负担，以及无法对开放式回答进行语义评估；二者共同造成持续存在的反馈缺口，阻碍学生学习成效的提升。为应对这些挑战，我们提出 Edhivo——一个AI原生的教学平台，通过面向内容交付、评估和报告的垂直集成系统来解决上述两个瓶颈。Edhivo 采用双LLM流水线：一个模型基于教师提供的材料，为多项选择题和开放式问题生成情境感知的评估内容；另一个模型则对学生回答进行多标准、基于评分量规的评估，从而在多个层级上实现近乎即时的定性反馈。所有AI交互均以来源为依据，以降低幻觉风险；同时，人在回路（Human-in-the-Loop）的审核流程保留了教师的权威。我们通过在石溪大学（Stony Brook University）2026年春季真实课堂环境中的试点部署，展示了 Edhivo 的有效性；在该部署中，它为一个由36名学生组成的队列在整个学期内支持高频评估的创建与评价，显著减少了编写负担和反馈延迟，同时支持以主动学习为中心的新型教学设计。

## Abstract
Scaling assessment in higher education faces two intertwined bottlenecks: the cognitive burden of authoring assessments and the inability to semantically evaluate open-ended responses, which together create a persistent feedback gap that hinders student learning outcomes. To address these challenges, we present Edhivo, an AI-native pedagogical platform that addresses both bottlenecks through a vertically integrated system for content delivery, assessment, and reporting. Edhivo employs a Dual-LLM pipeline: one model generates context-aware assessments for both multiple-choice and open-ended questions, from instructor-provided materials, while a second model performs multi-criteria, rubric-based evaluation of student responses, enabling near-instant qualitative feedback at multiple hierarchical levels. All AI interactions are source-grounded to reduce hallucination risk, and a Human-in-the-Loop review process preserves instructor authority. We demonstrate Edhivo's efficacy through a pilot deployment at Stony Brook University in a real classroom environment in 2026 spring, where it supports high-frequency assessment creation and evaluation for a cohort of 36 students throughout a full semester, significantly reducing authoring effort and feedback latency while enabling novel pedagogical designs centered on active learning.

## 1. 核心问题与研究动机

- **双重瓶颈**：高等教育评估规模化受制于两点——(1) 高质量评估的**编写认知负担**（审阅材料、命题、撰写答案键耗时耗力）；(2) 现有系统**缺乏对开放式回答的语义评估能力**，只能退化为选择题等浅层题型。
- **反馈缺口**：上述瓶颈共同造成"反馈缺口"——学生无法在知识尚新鲜时纠正误解，直接损害学习成效（引 Hattie & Timperley, 2007；Shute, 2008）。
- **现有工具定位偏差**：
  - 传统 LMS（Canvas、Blackboard/Brightspace）本质是行政枢纽，AI 仅作插件，评估仍以总结性、人工为主；
  - 互动响应系统（Kahoot、Slido）限于原子题型（主要是 MCQ），缺乏课程内容 grounding；
  - AI 学习助手（NotebookLM、Turbo.ai）具备来源 grounding，但缺少教师主导工作流、队列报告与量规评估。
- **论文主张**：提出 **Edhivo**——一个"AI 原生"而非"AI 外挂"的垂直集成平台，将内容交付、评估生成、自动评价与分层报告整合为一体，在保留教师权威的前提下同时缓解两个瓶颈。

## 2. 方法论

### 2.1 核心思想
- **双 LLM 流水线（Dual-LLM Pipeline）**：生成模型负责"出题"，独立评估模型负责"评分"，二者职责分离，避免同一模型自出自评。
- **来源 grounding**：所有 AI 交互被约束在教师上传的课程材料内，以降低幻觉风险。
- **人在回路（HITL）**：AI 输出必须经教师审核、修改或覆盖后方可发布，教师保留最终决定权。

### 2.2 关键技术细节
- **异构模型选型**（作者声明可替换）：
  - 评估生成用 **Gemini 3 Flash**：依托 1M+ token 上下文窗口，可整本教材/讲义不截断摄入；
  - 评估引擎用 **GLM 4.7 Flash**：指令遵循能力强，适合多准则评分。
- **结构化输出**：每次请求附带 JSON Schema，规定题目、选项、评分键的数据类型，保证编排层与 UI 之间的确定性状态。
- **并行生成**：教师分别指定 MCQ 与开放题数量，系统按题型各发一路并行请求，每路配专用 prompt 与针对性 few-shot 示例，防止"跨题型 prompt 漂移"。
- **生成 Prompt 结构**（Prompt 1）：`[角色] 专家命题者 + [上下文] 上传材料 + [约束] 题量与难度 + [格式] JSON Schema + [示例] few-shot`。
- **评分流程**（Prompt 2）：采用**思维链（CoT）+ 先推理后打分**，对三个显式准则逐一给出分步论证后再输出分数：
  - **Correctness（0–5）**：与参考答案的事实一致性；
  - **Completeness（0–5）**：关键概念覆盖度；
  - **Relevance（0–5）**：回答针对性、无冗余。
  - 最终输出 JSON：`{"scores": {correctness, completeness, relevance}, "justification": "..."}`。
- **分级反馈与报告**：报告引擎在四个粒度输出"教学健康度"快照——学生-单次评估、学生-课程纵向趋势、队列-单次评估分布（定位瓶颈概念）、队列-课程学期宏观进度。

### 2.3 平台工作流
- **教师端**：上传内容 → 审阅合成题目 → 修改/覆盖（或追加引导 prompt、或完全手写）→ 发布。
- **学生端**：自测出题并可"向教师提议"题目（众包题库）；同一套题可做 **pre/post 测评**，以分数差衡量学习增益；提交后即时获得定性反馈实现"即时补救"。

## 6. 主要结论与发现

- Edhivo 可在真实研究生课堂中**持续支撑整学期的高频形成性评估**（每节课约 3 轮 pre/post），而这在纯人工条件下"logistically impractical"。
- **出题效率**：单次评估准备时间由约 30 min 降至约 5.2 min（含 HITL），净省约 25 min。
- **反馈延迟**：开放式回答的整队列评分由线性人工工时（200 人约 16.6 h）压缩至秒级处理 + 审计（约 8.3 h 净省）。
- **成本**：200 人队列评分成本低于 $0.55，具备机构级可扩展性。
- **学生感知**：易用性与学习促进两项均获 100% 正向评价；即时 pre/post 对比被认为提升了展示环节的注意力与参与度。
- **总体判断**：AI 原生、垂直集成的架构能在**保留教师控制权**的同时，支撑以主动学习（含学生主导出题）为中心的新型教学法。

## 7. 优点

- **架构层面的分工设计**：生成与评估用两个异构模型解耦，避免自出自评的同源偏差，且明确声明模型可替换，降低供应商锁定风险。
- **工程可靠性考虑到位**：JSON Schema 强制结构化输出保证前后端状态确定性；按题型拆分并行请求 + 独立 few-shot，防止 prompt 漂移。
- **评分可解释性**：CoT + 三准则"先推理后打分"，输出含 justification，既降低评分任意性，也为教师审计提供依据。
- **双重风险控制**：来源 grounding（防幻觉）+ HITL（最终把关），并将 HITL 审计同时用作**提示策略的持续数据收集回路**，形成改进闭环。
- **教学法创新**：把 pre/post 测评嵌入学生主导的展示环节，用分数差作为学习增益的轻量度量，同时以"学生提议题目"众包题库，具有真实教学价值。
- **生态效度高**：真实课程、整学期、真实学生队列，而非一次性 demo。
- **报告粒度设计合理**：四级分析（学生/课程 × 单次/纵向）直接对应教师"定位瓶颈概念"的实际需求。

## 8. 不足与局限

- **评估证据薄弱（最核心问题）**：缺乏 AI 评分与人工评分的 IRR 定量分析，也无与其它自动评分基线的对比；"评分准确性"这一关键主张目前仅有 HITL 兜底，未获实证支持。
- **实验覆盖窄**：n=36、单一机构、单一课程、单一学科（STEM/LLM 课程），无法外推到大规模或多学科场景；无消融实验（如去掉 CoT、去掉 few-shot、换模型的影响均未知）。
- **基线为估算而非实测**：30 min 出题、5 min/人评分均为假设或单教师非正式估计，直接影响时间/成本结论的可靠性。
- **领域局限**：rubric 逻辑依赖"客观 ground truth"，在人文等主观学科是否成立尚未验证。
- **语言偏见风险**：使用 LLM 起草的回答可能因与评估模型风格对齐而获高分，从而不利于写作风格非标准的学生（作者已自承）。
- **无监考能力**：缺少全屏强制、切屏检测等机制，不适用于高风险/计分考试，限制了应用场景。
- **问卷方法学弱点**：自报数据、无对照组、无统计检验；"100% 同意"在小样本下易受社会期望与样本选择性影响。
- **成本数据时效性**：依赖特定供应商（OpenRouter/GLM）当前定价，随价格变动结论可能失效。
