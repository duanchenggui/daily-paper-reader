Abstract 

Scaling assessment in higher education faces two intertwined bottlenecks: the cognitive bur-den of authoring assessments and the inability to semantically evaluate open-ended responses, which together create a persistent feedback gap that hinders student learning outcomes. To address these challenges, we present Ed-hivo, an AI-native pedagogical platform that addresses both bottlenecks through a vertically integrated system for content delivery, assess-ment, and reporting. Edhivo employs a Dual-LLM pipeline: one model generates context-aware assessments for both multiple-choice and open-ended questions, from instructor-provided materials, while a second model per-forms multi-criteria, rubric-based evaluation of student responses, enabling near-instant qual-itative feedback at multiple hierarchical lev-els. All AI interactions are source-grounded to reduce hallucination risk, and a Human-in-the-Loop review process preserves instructor authority. We demonstrate Edhivo’s efficacy through a pilot deployment at Stony Brook Uni-versity in a real classroom environment in 2026 spring, where it supports high-frequency as-sessment creation and evaluation for a cohort of 36 students throughout a full semester, sig-nificantly reducing authoring effort and feed-back latency while enabling novel pedagogical designs centered on active learning. 1

2 Related Work 

The landscape of educational technology can broadly be characterized by three categories: legacy administrative systems, synchronous en-gagement tools, and emerging AI-powered study aids (Kasneci et al., 2023). While these categories increasingly overlap, each addresses a different slice of the instructional workflow. Edhivo inte-grates and extends these functionalities into a uni-fied, AI-native classroom solution specialized for assessment-based learning. Table 1 summarizes the key capability differences, with details below. 

Traditional LMS Canvas (Instructure, 2024) and Brightspace (D2L, 2024) excel at content hosting and gradebook management but treat AI as a plu-gin; their assessment models remain largely sum-mative and manual, leaving the feedback gap unad-dressed for open-ended responses. 

Interactive Response Systems Kahoot (Kahoot!, 2024) and Slido (Slido, 2024) enable gamified, real-time engagement but are limited to atomic question types (primarily MCQ) and lack persistent course-content grounding for qualitative feedback. 

AI-Native Study Aids NotebookLM (Google, 2024) and Turbo.ai (Turbo.ai, 2024) pioneered source-grounded AI for self-study but lack instructor-led workflows, cohort reporting, and rubric-based evaluation required for formal edu-cation. 

3 System Architecture 

The Edhivo architecture is structured as an AI Or-chestration Layer (Figure 1) that oversees the entire lifecycle of an assessment, from content ingestion to student reporting. 

3.1 Model Selection & Prompt Engineering 

We employ a strategy to use heterogeneous LLM models to optimize for both complex reasoning and system throughput: 3

• Assessment Generation: We utilize Gemini 3 Flash for its 1M+ token context window, allow-ing the system to ingest high-density course ma-terials (textbooks, transcripts) without truncation. • Evaluation Engine: We deploy GLM 4.7 Flash, which demonstrates high instruction-following capabilities for multi-criteria grading tasks. To maintain a deterministic state between the AI Orchestration Layer and the user interface, we leverage each model’s native structured output ca-pabilities. Each request includes a JSON schema that specifies the data types for questions, options, and grading keys. 

3.2 Assessment Generation Pipeline 

The generation pipeline transforms raw course con-tent into a deployable assessment through a user-configured, parallel generation process. The in-structor (or student, in self-study mode) specifies the desired number of MCQs and open-ended ques-tions independently, and the system dispatches parallel requests to the generation model—one per question type—each governed by a dedicated prompt with targeted few-shot examples (Brown et al., 2020) to prevent cross-type prompt drift. Each request follows the prompt template 1 below, combining a role definition, the ingested course context, user-defined constraints, and high-quality exemplars. 

Prompt 1: Assessment Generation Template 

> [Role]: Expert Academic Question Setter. [Context]: {uploaded_context} [Constraints]: Generate {n} questions at {level} difficulty. [Format]: Strictly follow the JSON schema { schema}. [Examples]: {few_shot_examples}

By enforcing strict schema adherence, the gen-erated content is immediately ready for Human-in-the-Loop review. Full prompts are provided in Appendix A.

3.3 Rubric-Based Automated Evaluation Engine 

Upon submission, the evaluation model performs a semantic comparison of each student response against the instructor-defined ground truth (Zheng et al., 2023; Liu et al., 2023). A Chain-of-Thought (CoT) (Wei et al., 2022) grading prompt (Prompt 2) forces the model to provide step-by-step justifica-tions across three explicit criteria—Correctness, Completeness, and Relevance—before assigning scores. This “reason-then-score” design aims to reduce grading arbitrariness and reflects calls for fine-grained, context-aware evaluation (Song et al., 2025; Zhou, 2026). 

Prompt 2: Grading & Justification Prompt (Abridged) 

> Task: Evaluate the [Student's Answer] against the [Reference Answer]. Evaluation Criteria: 1. Correctness (0-5): Factual alignment. 2. Completeness (0-5): Coverage of key concepts. 3. Relevance (0-5): Directness of response. Reasoning: Perform a step-by-step analysis of each criterion. Output: Return a JSON object with scores and a concise justification.

4 Platform Interfaces & Analytics 

4.1 Instructor Interface: Content-to-Assessment 

After creating a course and enrolling students, the instructor uploads source materials and the AI Or-chestration Layer proposes an assessment. The workflow follows: Upload Content → Review Syn-thetic Questions → Revise or Override → Publish. Instructors can (1) edit or replace AI-generated questions, (2) provide additional steering prompts to guide generation, or (3) author assessments fully manually without AI assistance. 4.2 Student Interface: Real-time Feedback Loop 

Students interact with a streamlined dashboard pro-viding three key capabilities: • Active Learning: Students can generate self-study assessments and “propose” questions to the instructor, crowdsourcing the question bank. • Pre/Post Assessment: The same assessment can be administered before and after learning; the score delta provides a direct measure of learning gain. • Instant Remediation: Upon submission, stu-dents receive qualitative feedback from the eval-uation engine (Section 3.3), enabling correction of misconceptions while material is fresh (Shute, 2008). 3Figure 3: A student feedback report featuring real-time insights.

4.3 Hierarchical Analytics & Reporting 

The reporting engine delivers a “Pedagogical Health” snapshot at four levels of granular-ity: (1) Student-Assessment —individual scores and feedback per test; (2) Student-Course —longitudinal trends across modules; (3) Cohort-Assessment —class-wide score distributions to sur-face bottleneck concepts; and (4) Cohort-Course —macro-level progress tracking over the semester. 5 Pilot Study: Real Classroom Deployment 

To evaluate its practical feasibility and pedagogi-cal utility, we conducted a pilot deployment in a real graduate-level classroom in Spring 2026. The deployment aimed to assess whether the platform could support high-frequency formative assessment with minimal feedback latency in a live instruc-tional setting. 

Course Context The platform was deployed in AMS 691.01: Foundations and Frontiers of Large Language Models at Stony Brook Univer-sity, with 36 graduate students from data science, computer science, and engineering backgrounds. The course covers the evolution of large language

Pedagogical Alignment & Reliability Although computational efficacy and cost savings are essen-tial for institutional scalability, grading precision remains our primary architectural concern. By collecting instruc-tor overrides and modifications, we can fine-tune the Evaluation Engine’s prompt strategy to better align with specific academic standards and departmental rubrics.

7 Conclusion 

We presented Edhivo, an AI-native pedagogical platform that closes the feedback gap in higher ed-ucation through a vertically integrated system for content delivery, assessment generation, and auto-mated evaluation. Our pilot deployment at Stony Brook University demonstrates significant reduc-tions in instructor workload and feedback latency at minimal infrastructure cost. Future work will focus on formal Inter-Rater Reliability analysis across larger, multi-disciplinary cohorts and expanding the platform’s applicability beyond STEM disci-plines. 

Limitations 

While Edhivo demonstrates significant potential in reducing the assessment authoring, management, and evaluation gaps, several limitations remain. First, the platform lacks proctoring safeguards 

such as full-screen enforcement and tab-switch de-tection, which are critical for high-stakes testing. This is a common challenge in digital assessment, especially as AI advances. Second, our evaluation engine may be suscep-tible to linguistic bias; students using LLMs to draft responses might receive higher scores due to stylistic alignment between models (Zheng et al., 2023), potentially disadvantaging students with non-standard writing styles. Third, the domain-specific efficacy of the plat-form is currently centered on STEM-related sub-jects with objective ground truths. Further research is required to determine if the rubric-based logic holds for more subjective disciplines such as the humanities. Additionally, reported time savings for manual authoring (Section 6) are informal estimates from a single instructor, not controlled measurements across multiple instructors or disciplines; actual authoring times may vary with subject complexity and individual workflows. Finally, our classroom pilot was limited to a small cohort ( n = 36 ) at a single institution, and our evaluation data derives from a single course context. Future work will focus on longitudinal studies across larger, multi-disciplinary student bodies to better assess the Inter-Rater Reliability (IRR) between the AI Orchestration Layer and hu-man expert graders. 6Ethics Statement 

This work involves the collection and processing of student assessment data and survey responses in an educational setting. No personally identifiable student data was collected or retained. All survey participation was voluntary, and responses were anonymized prior to analysis. We acknowledge that AI-based evaluation may introduce linguistic bias, potentially favoring re-sponses stylistically aligned with the evaluation model’s training data. This risk is discussed in the Limitations section. The HITL audit process serves as a safeguard to prevent unverified AI scores from impacting official student records.

A.1 Evaluation Prompt: Rubric-Based Grading 

The following prompt is used by the evaluation engine to score student responses against instructor-defined ground truth. The prompt employs Chain-of-Thought reasoning to ensure transparent and consistent grading. 

You are an expert Teaching Assistant grading an open-ended question. Your goal is to provide a fair and consistent evaluation based on a provided rubric. **Question:** {question} **Reference Answer (The ideal answer):** {ground_truth} **Student's Answer:** {given_answer} ---**Evaluation Task:** Please evaluate the student's answer against the reference answer using the following rubric . Provide your reasoning step-by-step (chain -of-thought) before giving the final output. **Rubric:** 1. Correctness (0-5 points): Is the student's answer factually correct and aligned with the reference answer? (5 = Completely correct, 0 = Completely incorrect). 2. Completeness (0-5 points): Does the answer address all key concepts and parts of the question present in the reference answer? (5 = All key concepts covered, 0 = No key concepts covered). 3. Relevance (0-5 points): Is the answer directly addressing the question asked, without irrelevant information? (5 = Perfectly relevant, 0 = Completely irrelevant). **Chain of Thought (Your reasoning):** * Correctness Analysis: [Examine factual accuracy...] * Completeness Analysis: [Identify missing concepts...] * Relevance Analysis: [Assess directness and focus...] **Final Output:** Provide your final scores and overall judgment in a JSON object. {"scores": { "correctness": <score_1>, "completeness": <score_2>, "relevance": <score_3> }, "justification": "<A concise summary of your reasoning>" }
