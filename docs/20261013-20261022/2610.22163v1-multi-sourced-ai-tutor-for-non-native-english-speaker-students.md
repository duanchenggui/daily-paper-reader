## 摘要
大语言模型（LLMs）正越来越多地被用作计算机教育中的教学工具，尤其是用于开发能够回答学生问题的AI辅导系统。随着计算机类专业中国际学生入学人数增加，研究者开始探讨非英语母语（NNES）学生在计算机课程中因语言障碍而面临的困难。为帮助此类学生，我们开发了一个通用AI辅导系统，能够处理学生用外语（目前主要聚焦于普通话）提出的问题，并提供双语回答。该系统还具备生成技术术语表及其解释的功能，以增强理解。我们的方法采用专门的检索增强生成（RAG）流水线，并引入一种新颖的问题提取机制，使我们能够有效利用多样化的课程材料来回答学生查询。我们使用91条Piazza帖子对AI辅导系统进行了评估，结果表明它能正确且有益地回答83.52%的帖子。该辅导系统还为76.92%的问题提供了高质量翻译，并为64.47%的问题生成了技术术语表。我们的发现凸显了多源RAG流水线在增强AI辅导系统方面的潜力，可为那些难以通过计算机课程传统支持人员获得帮助的非英语母语者提供支持。

## Abstract
Large language models (LLMs) are increasingly being adopted as teaching tools in computing education, particularly for developing AI tutors capable of answering student questions. With the rise in enrollment of international students in computing programs, researchers have begun to explore the difficulties that non-native English speaker (NNES) students face in computing courses due to language barriers. To aid such students, we developed a general-purpose AI tutor system that can process student questions in foreign languages (currently focused on Mandarin) and provide bilingual responses. Our system also incorporates the functionality of generating a glossary of technical terms and their explanations to enhance comprehension. Our approach utilizes a specialized Retrieval-Augmented Generation (RAG) pipeline with a novel question extraction mechanism, enabling us to effectively utilize a diverse array of course materials for answering student queries. We evaluated our AI tutor using 91 Piazza posts, demonstrating that it could answer 83.52% of the posts correctly and in a helpful manner. The tutor also provided high-quality translations for 76.92% of the questions and generated technical term glossaries for 64.47% of them. Our findings underscore the potential of multi-source RAG pipeline in enhancing AI tutor systems, offering support for non-native speakers that are challenging to provide with traditional supporting staff of a computing course.

- **核心问题**：NNES 学生在计算机课程中面临词汇、语法、口音、俚语等语言障碍，以及怕犯错、怕被误解的自信问题，往往不愿主动向教师或助教求助；现有 AI 辅导系统多基于单一来源（教材、讲义字幕或作业文档）构建 RAG，难以覆盖课程中多样化、异构的材料。
- **论文目标**：开发一个通用 AI 辅导系统，允许学生用母语（当前为普通话）提问，系统输出英汉双语回答，并生成技术术语表；通过多源 RAG 与专门的问题抽取机制，提升答疑的准确性、上下文相关性和可访问性，从而为非英语母语学生提供传统助教资源难以覆盖的支持。
- **整体含义**：该工作将“多源课程材料整合”“题号引用解析”“翻译前置”“双语术语解释”结合到同一 AI 辅导流水线中，探索了 AI 辅导系统在计算教育公平性与包容性方面的潜力。

## 2. 方法论

### 2.1 核心思想

- 构建一个 **四阶段流水线**：翻译（Translation）→ 问题抽取（Question Extraction, QE）→ 检索增强生成（RAG）→ 回答生成（Response Generation）。
- 与既有单源 RAG 系统不同，该系统将讲义、幻灯片、工作表、补充阅读、项目/实验仓库、课程网站、测验与历年考试等 **多源异构课程材料** 统一解析并存入向量库。
- 针对真实 Piazza 帖子中“只写题号、不写题目内容”的普遍现象，设计专门的问题抽取阶段，将题号标准化后从题库中取回原题，再交给 RAG 与生成阶段使用。

### 2.2 数据与问题分类

- 收集某学期中级数据科学（DS）课程（约 400 名学生）的 **620 条 Piazza 帖子**。
- 排除 **238 条含图片帖子**（难以转写、图表复杂，且 GPT-4 视觉 API 成本过高），保留 **382 条文本帖子**。
- 清洗：去重、移除可识别信息、清理 HTML、将代码片段和报错信息放入反引号。
- 按课程文件夹与内容分为四类：
  - 后勤（logistics）：90 条
  - 概念（conceptual）：54 条
  - 环境配置（environment setup）：41 条
  - 编程（programming）：197 条
- 使用 Google Translate API 将帖子翻译为普通话，并由中文母语作者逐条人工校对，形成中文数据集；反引号内代码不翻译。

### 2.3 四阶段流水线

- **翻译阶段**
  - 输入为英文原帖或人工校验的中文帖子。
  - 中文问题先经 Microsoft Azure AI Translate API 转为英文，再进入后续 RAG。
  - 选择“先翻译”而非直接用中文专用 LLM，是为了利用 GPT-4 在编程语境下的能力；翻译组件被设计为模块化、可替换。

- **问题抽取（QE）阶段**
  - 约 **35%** 的帖子涉及具体项目、测验或考试题，但仅在标题中写题号（如 “P2 Q10”“FA22 Exam 2 Q10”），正文不含题目内容。
  - 使用 **Llama 3 8B**（通过 Ollama 部署）进行 few-shot 题号标准化生成；提示词包含任务描述、输入格式、课程材料说明、输出格式和示例。
  - 将标准化题号输入 **基于规则的算法**，从题库中取回原题内容。
  - 题库构建：历年考试与答案 PDF 用 `fitz` 解析，Canvas 测验通过 Canvas API 获取，保存为文本文件。
  - 论文论证 QE 不可被 RAG 替代：题号短且多为数字，embedding 检索困难；题号缩写形式多样（如 “Project 2 Question 10” 与 “Fall 2022 Midterm 2 Question 10”），关键词检索也不稳定。

- **RAG 阶段**
  - 使用 **LangChain** 组织流程，**FAISS** 作为向量库，**OpenAI text-embedding-ada-002** 作为嵌入模型。
  - 多源材料及解析方式：
    - Jupyter Notebook → `nbconvert` 转为 Python 脚本；
    - PPT → `pptx2md` 转为 Markdown；
    - PDF → `fitz` 转为 Markdown；
    - Markdown/HTML → LangChain Header Text Splitter，再以 `RecursiveCharacterTextSplitter` 切分过长块；
    - Jupyter Notebook → 修改版 Markdown Header Splitter，再递归切分。
  - 每个 chunk 保留来源名称，便于生成回答时引用。
  - 检索时输入 **学生原帖 + 抽取出的题目内容**，返回 **Top-10** 相关结果。
  - **刻意排除历年考试与 Canvas 测验**：避免检索结果被相似考题淹没，导致讲义材料无法被召回；考试/测验仅在 QE 阶段使用。

- **回答生成阶段**
  - 使用 **Microsoft Azure OpenAI GPT-4 API**。
  - 系统提示词要求模型：
    - 扮演面向 NNES 学生的 AI 导师；
    - 不直接给出答案，只提供提示、解释或建议；
    - 避免输出代码片段；
    - 使用来源路径引用 RAG 结果；
    - 同时用英文和中文回答；
    - 将可能造成理解困难的技术词汇或报错信息整理为术语表。
  - 用户提示词包含：原始学生帖子、抽取出的题号与题目内容、RAG 检索结果。

## 3. 实验设计

- **数据集/场景**
  - 单门中级数据科学课程、单学期 Piazza 帖子。
  - QE 与 RAG 的重叠分析覆盖全部 **382 条** 文本帖子。
  - 回答生成评估使用 **91 条帖子** 的测试集：
    - 每类中浏览量最高的 **15%** 帖子；
    - 其余帖子中每类随机抽取 **10%**；
    - 构成：21 条后勤、14 条概念、9 条环境配置、47 条编程。
  - 该设计兼顾“学生最关注的问题”和“较少见但可能更具挑战性的问题”。

- **Benchmark 与参照**
  - 论文 **没有使用标准公开 benchmark**，而是自建 Piazza 帖子测试集，以人工评估作为 ground truth。
  - 由于无法对英文、中文、翻译后帖子都完整评估四阶段，作者将 **英文帖子的 QE 与 RAG 结果视为参照基准**，通过计算英文与中文/翻译后结果的 **重叠比例** 来间接评估中文与翻译后帖子。
  - 回答生成阶段仅评估 **翻译后帖子**，因为作者发现中文帖子在 RAG 阶段表现较差。

- **评估指标**
  - **QE 准确率**：当原帖信息足以确定具体题目时，是否正确输出题号；无法确定时是否不输出。
  - **QE 重叠率**：英文与中文/翻译后帖子 QE 结果的重叠百分比。
  - **RAG 相关性（relevance）**：
