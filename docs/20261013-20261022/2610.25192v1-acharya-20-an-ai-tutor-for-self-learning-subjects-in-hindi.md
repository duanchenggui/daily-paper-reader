## 摘要
文本处理对低资源语言至关重要，因为它能够促进工具与技术的开发，从而弥合数字鸿沟，并提供公平的信息与服务获取机会。通过为低资源语言赋能强大的文本处理能力，我们可以在快速数字化的世界中保护语言多样性、促进教育、改善交流并增强包容性。由于缺乏足够的标注数据集和语言资源，为这些低资源语言开发准确可靠的语言技术颇具挑战。大语言模型（LLMs）因其性能和所产生的价值而受到广泛关注。然而，随着语言不断演变，使 LLMs 适配特定任务既耗时又资源密集。因此，检索增强生成（RAG）通过利用外部知识增强 LLMs，克服了这一局限，从而提升了其效率并促进了广泛的任务特定适配。RAG 技术的大多数应用局限于英语，在印度语言中的应用也较为有限。本文介绍了一款由 RAG 驱动的 AI 导师应用 Acharya 2.0，旨在为印地语学生提供学业帮助。该基于客户端-服务器的 Web 应用集成了多项功能，以支持学生访问教育内容并与之交互。

## Abstract
Text processing is crucial for low-resource languages as it enables the development of tools and technologies that bridge the digital divide and provide equitable access to information and services. By empowering low-resource languages with robust text processing, we can preserve linguistic diversity, enhance education, improve communi- cation, and foster inclusivity in a rapidly digitizing world. Due to the lack of sufficient annotated datasets and lin- guistic resources, it is challenging to develop accurate and reliable language technologies for these low-resource languages. Large Language Models (LLMs) have attracted sig- nificant attention with their performance and the value they produce. However, with the ever-evolving language, adapting LLMs for a specific task is time-consuming and resource-intensive. Thus, Retrieval-Augmented Genera- tion (RAG) has overcome this limitation by augmenting LLMs with external knowledge, thereby improving their efficiency and extensive task-specific adaptation. Most applications of the RAG technique have been limited to English and has seen limited application in In- dic languages. This paper introduces the RAG-powered AI-Tutor application, Acharya 2.0, designed to produce academic assistance to Hindi-speaking students. The client-server-based web application integrates many fea- tures to support students in accessing and interacting with educational content.

## 二、方法论

### 2.1 核心思想
采用 **检索 + 生成（RAG）** 范式：将 CBSE 公开教材经 OCR 抽取、清洗、切块（chunking）、向量化后存入向量库；用户提问时先做语义检索，取回最相关的课程片段作为上下文，与问题一同填入提示模板送入微调后的印地语 LLM 生成答案。系统以客户端—服务器 Web 应用形式交付，桌面与手机均可访问。

### 2.2 系统架构与请求流程
- **前端**：React + Tailwind CSS 重写界面；`react-oauth` 接入 Google Identity Services 实现 Gmail 账号登录；集成 Google Transliteration 提供印地语输入；支持历史会话回看。
- **后端**：FastAPI 暴露主要路由，流程如下：
  1. `/google/oauth/token`：处理 Google OAuth 令牌与用户信息，完成认证；
  2. `/setting`：用户选择年级与科目，系统为其绑定对应的 ChromaDB collection；
  3. `/home`：用户输入 → 转为向量 → 从 ChromaDB 检索 **top-3** 相关文档 → 检索上下文 + 原始问题经提示模板送入 LLM → 生成回答；
  4. `/logout`：安全登出。
- **会话管理**：服务端记录用户活动（session），支撑历史对话功能。
- **关键组件**：retriever 与 LLM 是决定系统表现的两大模块；作者明确指出系统性能"在很大程度上取决于"这两者。

### 2.3 数据准备（RAG 知识库）
- **来源**：CBSE 官网公开教材（https://www.cbse.gov.in/），覆盖 2–12 年级（摘要与架构部分则称支持 1–12 年级，文中存在表述不一致）。
- **抽取**：使用 `pytesseract` 0.3.10（Tesseract-OCR 的 Python 封装）做 OCR。
- **清洗**：人工复核，修正 OCR 引入的拼写与标点错误。
- **规模**：约 **4.3M tokens**，覆盖 **13 个学科门类 / 全年级共 59 个科目**（会计、生物、商业研究、化学、物理等）；其中 12 年级含 13 个科目、222 份文档、1.29M tokens。

### 2.4 向量化与检索
- **嵌入模型**：`intfloat/multilingual-e5-large-instruct`（sentence-transformers）。
- **向量库**：ChromaDB 的 persist 目录（内存模式）。
- **相似度**：余弦相似度；检索返回 top-3 文档片段。
- 论文强调检索系统需在"有效性"与"效率"（磁盘/RAM/GPU 开销）之间权衡。

### 2.5 生成模型（LLM 微调）
- 探索了两个候选：
  - **Mistral-7B**：用 **80K** 条印地语指令（覆盖艺术、体育、环境、历史、食物、音乐等领域知识）微调，发布为 `OdiaGenAI/mistral_hindi_7b_base_v1`；
  - **Gemma-2B**：用 **188K** 条指令微调，指令集由多个公开印地语指令集合并而成；选其作基座是因其在若干基准任务上的表现。
- **最终选型**：综合比较后，Acharya 2.0 集成 **微调后的 Mistral-7B**。
- 作者补充观察：Gemma 的分词器对印度语言更高效（同一印地语句子切出的 token 更少），但模型规模差异（7B vs 2B）被认为是性能差距的主因，此点"需进一步研究"。

## 三、实验设计

- **评测对象**：同一 RAG 流水线下替换生成模型的两个版本——Mistral-7B-based RAG 与 Gemma-2B-based RAG。**没有**"无 RAG 的纯 LLM"基线，也没有与其他 ITS 或商用模型对比。
- **测试数据/场景**：覆盖多主题、多学科的问答；人工评测使用 **50 组问答对**。论文未说明自动评测所用的测试集规模、来源与构造方式（是否为 CBSE 习题、是否人工标注参考答案等）。
- **Benchmark / 指标**：
  - **自动指标**（均为 0–1）：
    - **BERTScore**（Precision / Recall / F1）：输出与参考答案的 token 级语义匹配；
    - **Cosine Similarity**：输出与参考答案向量表示的余弦相似度；
    - **RAGAS** 三项：**Faithfulness**（忠实度）、**Context Precision**（上下文精确率）、**Answer Relevancy**（答案相关性）。
  - **人工指标**（0–5 分）：**Readability**（可读性）、**Correctness**（正确性）、**Perplexity**（困惑度，越低表示幻觉越少）；3 名有同类评测经验的印地语母语标注者评分后取平均。
- **主要数值结果**：

| BERTScore-R | 0.699 | 0.629 |
| BERTScore-F1 | 0.698 | 0.652 |
| Cosine Similarity | 0.545 | 0.202 |
| RAGAS Faithfulness | 0.481 | 0.407 |
| RAGAS Context Precision | 0.275 | **0.487** |
| RAGAS Answer Relevancy | 0.247 | **0.321** |

## 六、主要结论与发现

- Acharya 2.0 作为端到端 RAG 教育应用可"较好地运行"，在 12 门核心学科（数学、科学、印地语、历史、地理等）上取得可接受的评测表现，且两模型推理延迟均较低。
- **Mistral-7B 版本整体优于 Gemma-2B 版本**：BERTScore F1（0.698 vs 0.652）、余弦相似度（0.545 vs 0.202）、Faithfulness（0.481 vs 0.407）以及人工评测多数指标均领先；作者归因于参数量差异（7B vs 2B）。
- **例外**：Gemma 在 RAGAS 的 Context Precision（0.487 vs 0.275）与 Answer Relevancy（0.321 vs 0.247）上反而更好，暗示其检索上下文利用或答案聚焦方式不同；Gemma 分词器对印度语言更高效，值得进一步研究。
- **学科强弱**：Mistral 版本在**数学与历史**上表现最佳。
- **典型失败模式**：
  - Gemma 版本产生较多错误与**空回答**，且词首/词尾字符缺失——作者认为改进 retriever 可缓解；
  - 部分回答"完全可读、无幻觉"，但**事实性错误**——即流畅性与正确性脱钩。
- **未来工作**：扩展至其他印度语言；通过嵌入微调与 re-ranking 提升检索器；用 OCR 纳入图像与表格；加入元数据；支持印地语语音转文本。

## 七、优点

- **填补场景空白**：将 RAG 从英语迁移到印地语 K-12 教育这一低资源、低覆盖场景，工程落地完整（认证、年级/科目选择、会话历史、移动端适配），且免费开放，具有实际可及性价值。

## 九、启示与可借鉴之处

- **"公开教材 + OCR + 人工清洗 + 向量库"是一条低成本的领域知识库构建路径**，对资源匮乏语种与地区具有较强可复制性：无需构建大规模标注语料，即可让通用 LLM 具备课程对齐能力。
- **以"年级 × 科目"为单位的 collection 隔离设计**，是一种简单有效的检索范围约束手段，能在不引入复杂路由模型的前提下显著缩小语义搜索空间，值得同类 K-12 系统借鉴。
- **双轨评测（自动语义指标 + 母语者人工评分）** 对低资源语言系统是务实选择；其中 RAGAS 的 Faithfulness 与 Context Precision 的"分离"现象（一个模型忠实度高但上下文精确率低）提示：**生成质量与检索质量应分开诊断**，否则容易把检索缺陷误判为生成缺陷。
- **分词器效率与模型规模的混淆**被作者主动指出，是一个有价值的方法论提醒：在多语/低资源场景下比较模型时，tokenization 的语种适配度会系统性影响成本与效果，应作为控制变量纳入实验设计。
- **诚实报告失败案例**（空回答、字符截断、事实性错误）为后续研究者提供了明确的优化靶点：检索器微调、re-ranking、空回答检测与重试机制。

## 十、总体评价

**定位**：本文属于**系统演示 / 工程实践型论文**（system demo paper），核心贡献在于"把 RAG 落到印地语 K-12 教育这一空白场景"并给出完整的端到端实现与初步评测，而非提出新的算法或理论。

**贡献强度**：
- 场景与工程贡献：**中—高**。面向低资源语言教育的免费可用系统，覆盖 59 个科目、4.3M tokens 的知识库，具备真实可及性价值。
- 方法与实验贡献：**低—中**。RAG 流水线为成熟范式的直接套用，无方法创新；评测仅 1 组模型对照、无消融、无基线、无用户研究，统计严谨性不足。
- 结论可靠性：**初步验证级**。Mistral 优于 Gemma 的结论受参数量（7B vs 2B）与微调数据量（80K vs 188K）双重混淆，且 Gemma 在两项 RAGAS 指标上反超，说明结论不宜过度推广。

**一句话总结**：Acharya 2.0 是一次**方向正确、落地扎实、验证偏弱**的低资源语言教育 RAG 实践——它证明了"印地语 K-12 学业问答可以被低成本地构建出来"，但尚未证明"它作为导师是有效的、可靠的、可扩展的"。

**若要提升至更强论文，优先补齐三件事**：① 加入 no-RAG 基线与检索器专项评测（Recall@k / MRR），厘清瓶颈在检索还是生成；② 在参数量或数据量上做控制变量的公平对比，并补 top-k、chunk 策略的消融；③ 开展小规模真实学生用户研究，报告学习增益与可用性指标，同时给出延迟与成本的量化数据。
