## 摘要
教师越来越多地通过自然语言指令配置教育聊天机器人，但这些机器人在真实使用中如何失败仍鲜为人知。我们提出 EduWild，这是一个包含 1,726 段对话的数据集，涉及 217 个教师配置的聊天机器人，每段对话都配有背后的指令和配置，其中包括来自 35 个已部署聊天机器人目标终端用户的 900 段对话。我们开发了一个包含 29 个代码的分类体系，涵盖事实性、工作流、诊断性和教学性失败，并使用经人工校准的 LLM 评判器加以应用。最常见的失败是未能遵循教师意图——机器人跳过必需的工作流步骤（占终端用户对话的 53.8%）、省略期望设定（33.4%），以及用信息或问题使学习者过载（37.1%）。在这些发现的指导下，我们设计了一种基于提示的框架，针对六种最常见的失败模式。在一项涉及十款机器人、200 名大学生的研究中，该框架将每段对话中目标失败代码的平均数量从 1.406 降至 0.489，在机器人等权加权下相对降低 65.2%。这些发现表明，真实世界的失败分析可以如何指导教育聊天机器人的实际改进。

## Abstract
Teachers increasingly configure educational chatbots through natural-language instructions, but how these bots fail in real-world use remains poorly understood. We introduce EduWild, a dataset of 1,726 conversations with 217 teacher-configured chatbots, each paired with the instructions and configuration behind it, including 900 conversations from the intended end users of 35 deployed chatbots. We develop a 29-code taxonomy covering factual, workflow, diagnostic, and pedagogical failures and apply it using a human-calibrated LLM judge. The most frequent failures are lapses in following teacher intent --- bots skip required workflow steps (53.8% of end-user conversations), omit expectation setup (33.4%), and overload learners with information or questions (37.1%). Guided by these findings, we design a prompt-based harness targeting the six most frequent failure modes. In a study with 200 college students across ten bots, the harness reduces the mean number of target failure codes per conversation from 1.406 to 0.489, a 65.2% relative reduction with bots weighted equally. These findings show how real-world failure analysis can guide practical improvements to educational chatbots.

## 1. 核心问题与整体含义

- **研究动机**：越来越多教师通过自然语言系统提示（system prompt）在无代码平台上配置教育聊天机器人，但这类机器人在真实课堂/课程使用中**如何失败**缺乏系统理解。已有数据多为合成对话、模拟学生、众包工人或单一通用聊天机器人，且很少把“对话”与“教师原始指令和配置”配对，因而无法判断机器人是否遵循了教师意图。
- **核心问题**：教师配置的聊天机器人在真实终端用户对话中会出现哪些失败模式？这些失败能否通过轻量、可部署的干预显著减少？
- **整体含义**：论文主张教育聊天机器人的评估不能只看“答案是否正确”，还应关注**工作流遵循、边界遵守、期望设定、认知负荷与教学时机**。作者用真实部署数据建立失败分类法，再据此设计提示级防护框架（harness），形成“真实失败分析 → 针对性改进 → 人类被试验证”的闭环。

## 2. 方法论

### 2.1 数据集 EduWild 的构建

- **来源**：某高校九周在线教师专业发展项目（2025年2月—2026年7月），教师在 Playlab 平台上以自然语言提示构建并自愿共享聊天机器人。
- **规模**：87 名教育者创建 224 个机器人、1,744 段对话；清洗后保留 **217 个机器人、85 名教育者、1,726 段对话（17,982 条消息）**。
- **两层数据**：
  - **作者层数据**：每个机器人的系统提示、标题、描述、模型、附件文件、平台设置、发布状态等。
  - **交互层数据**：完整对话记录、角色、时间戳、HTML 格式、附件等。
- **用户分组**：终端用户 900 段（35 个已部署机器人）、机器人作者 741 段、其他教育者 85 段。失败分析只使用 **900 段终端用户对话**，因为作者与同伴对话主要反映测试和探索。
- **数据特点**：部署机器人的提示更长（中位数 500 词 vs 全部 296 词），91% 附带至少一个参考文件；73% 使用 Claude 模型（部署机器人中 86% 为 Claude Sonnet 4.6），23% 使用 GPT 模型。终端用户对话中位数 7 条消息、每条用户消息 9 词、回复间隔 59 秒、会话时长 3.2 分钟；使用集中在少数机器人（前 5 个占 56.4% 对话），因此后续分析对机器人等权。

### 2.2 29 码失败分类法与标注

- **分类法结构**：4 个一级类别、29 个二级代码：
  - **Factual（7 码）**：错误内容、内容不完整、内部不一致、 grounding 失败、护栏越界、偏离任务、过度拒答。
  - **Workflow（9 码）**：学生放弃、学生问题未答、机器人问题未答、输出截断、重复循环、多问题过载、跳过/缺失流程、语言格式不匹配、无期望设定。
  - **Diagnostic（6 码）**：未诊断即教学、误判水平、漏判错误、误判正确为错误、忽略学习者信号、误识别请求。
  - **Pedagogical（7 码）**：答案倾倒、过度脚手架、认知过载、策略—任务不匹配、认知参与不足、反馈质量差、失败后不恢复。
- **理论来源**：LearnLM、MathDial、MRBench、ICAP、KLI、人机交互指南、红队研究等；其中 W7、W8 为数据归纳产生。
- **标注流程**：
  1. 两名作者独立标注 45 段随机评估样本（约 5%）和 10 段示例池，人工一致性 **Cohen’s κ = 0.71**；
  2. 讨论分歧形成共识标签并修订码本；
  3. 用共识码本与 10 段示例构建 **GPT-5.6-Sol LLM 评判器**，在未见于提示的 45 段评估样本上达到 **κ = 0.85**；
  4. 用该评判器标注其余对话。
- **标签粒度**：对话级二值标签（某失败模式是否出现），一段对话可含多个失败码。

### 2.3 提示级 Harness

- **核心思想**：不改动教师原始提示，在其外层加一个提示级包装器，针对语料中 prevalence 超过 10% 的六个失败码：**W7（跳过流程）、W9（无期望设定）、P3（认知过载）、W6（多问题过载）、F5（护栏越界）、F1（错误内容）**。
- **三个组件**：
  1. **失败专用提示**：每个目标码对应一段控制指令，例如 W7 要求“跟随适用工作流、承认学生贡献、不重复已完成步骤”；W6 要求“每轮只请求一个新信息或一个小行动”；P3 要求“先给所需答案或下一步，宽泛任务给紧凑路线图，约 180–300 词”；F5 要求“尊重教师任务边界与例外”；F1 要求“区分可见事实、常识与不可验证信息，检查推理与计算”；W9 要求“开场简要说明角色、范围与互动方式”。
  2. **开场自我介绍**：在学生发言前，由一次独立调用生成简短欢迎语，说明角色与范围，并包含教师要求的开场问题，作为对话历史第一条消息。
  3. **教师意图记忆**：交互前由 LLM 从教师原始提示中抽取“学习者责任”，输出 JSON 数组，每项含 `requirement` 与 `source_quote`；实现上校验引文必须是原提示的连续子串，并按提示与抽取器版本缓存，跨轮次复用。响应时把原始教师提示、六个控制提示、缓存的教师意图、对话历史与学生输入拼接后交给 tutor LLM 生成回复。
- **运行时限制**：参考实现只能获得附件文件名与数量，不能读取附件正文；提示中明确要求不得声称读过文件、不得从文件名推断具体政策或日期。
- **算法流程（文字版）**：
  - 准备阶段：教师提示 → LLM 抽取学习者责任及支持引文 → 校验并缓存；
  - 开场阶段：教师提示 + 初始化指令 → 生成欢迎语；
  - 每轮响应：教师提示 + 六个失败控制 + 轮次提醒 + 教师意图记忆 + 对话历史 + 学生消息 → tutor LLM → 回复。

### 2.4 评估指标与统计

- **主指标**：每段对话中出现的**不同目标失败码数量**（F1、F5、W6、W7、W9、P3，范围 0–6）。
- **次指标**：全部 29 码的平均数量、至少含一个目标失败码的对话比例、各单码 prevalence。
- **统计**：对 10 个机器人等权平均；按“机器人与条件内参与者”做 bootstrap 估计 95% 置信区间；prevalence 差异以百分点表示。
